# 软件项目镜头

在 `SHAPE` 和 `STRESS TEST` 按需检查；不要把每项都变成问题。

- 架构：系统边界、组件职责、依赖和关键状态如何划分？
- 接口：输入输出、数据契约、权限、错误语义和兼容性是什么？
- 迁移：现有数据或行为如何迁移，如何分阶段发布与回滚？
- 安全：威胁、隐私、身份与授权、密钥和合规门槛是什么？
- 性能：延迟、吞吐、容量、资源与成本预算是什么？
- 运维：可观测性、故障响应、恢复、所有权和运行手册需要什么？
- 测试：单元、集成、端到端、回归和验收如何覆盖核心及异常路径？

将每个里程碑写成可观察的用户或系统结果，并配验收检查。高风险变更优先用 spike、原型或受限发布验证关键假设。
